## 4.22 拿到CC3M数据集并做数据集的所有处理

CC3M体量比预期小一点，在270G左右，包含训练集与验证集，刚好留了一部分当作验证集，很不错！不过光下载就花了一个早上。

数据集的处理工作第一阶段主要有几个方向，包括数据集的合并，数据集的筛选（主要针对于CC3M）

1. 关于数据集的合并，先进行的是flickr与coco captions的合并，遇到了昨天没有遇到的问题，报错image_id重复，这里还得区分image_id以及filename。这里最初的想法是将flickr的重复id变为max(coco_id+1)这样可以避免与coco的重复，但是这里有逻辑漏洞，尽管避免了与coco的重复，但是没有避免与flickr自身的重复。后面将逻辑修改为如果有一个重复，就把所有flickr_id进行修改，全部改到coco_id+1之后的区间（主要考虑flickr的体量不如coco captions）这样解决了所有的问题。然后进行的是

2. 关于数据集的筛选，对于coco captions数据以及flickr数据，整体由人工标注，符合标注需求；但是CC3M数据从网络上提取，整体文本质量甚至图像质量不尽如人意，这里需要适当的进行数据筛选。

```text

D:\DINO\dinov3\try_txt_png\verify_coco_pair.py
可以有效的验证文件路径的正确以及图像文本的可读性。
=======================================================================
D:\DINO\dinov3\try_txt_png\convert_cc3m_tars_to_coco_captions.py
可以直接从CC3M的片段化的tar文件中解压出图像并包装成coco captions的结构，并进行筛选。CC3M数据必须经过筛选！否则影响过大

python dinov3/try_txt_png/convert_cc3m_tars_to_coco_captions.py --tar-dir "e:\DATASET\cc3m" --out "e:\DATASET\cc3m_coco_filtered" 

```

这里筛选的维度包括：

| 过滤维度 | 参数 | 默认值 | 作用 |
|--------|------|--------|------|
| 1. 状态过滤 | `meta["status"]` | 必须为 `"success"` | 跳过爬取失败或低质量样本（img2dataset 的标准字段） |
| 2. 图像尺寸 | `--min-width`<br>`--min-height`<br>`--min-short-side` | `0, 0, 256` | 去掉太小的图（避免模糊/无信息量） |
| 3. 长宽比 | `--max-aspect` | `3.0` | 去掉极端横图或竖图（如 banner、长截图） |
| 4. Caption 长度 | `--min-caption-chars`<br>`--max-caption-chars` | `5, 180` | 去掉太短（无意义）或太长（可能含噪声）的文本  |
| 5. 文本内容黑名单 | `--ban-regex` | 包含 `http`, `www`, `buy now`, `free shipping` 等 | 关键！ 过滤广告、URL、SEO 垃圾文本  |
