## 一、整体定位：把多视角 3D 重建变成 decoder-only Transformer

STream3R 沿用了 DUSt3R / VGG-T 这一系"用 Transformer 直接回归 pointmap"的范式（不依赖全局 BA / 全局优化），但把跨帧注意力从**全双向 (full attention)** 改成了 **causal attention**，从而：

- 像 GPT 一样**逐帧流式**地处理图像序列；
- 天然兼容 **KV cache、Flash-Attention、Sliding-Window**；
- 一帧来了只需 attend 到历史帧的 K/V，**实时性强**（README 给的数据：window 模式下 200 帧推理仍稳定在 ~0.15s/帧，显存恒定 6.53 GB）。

模型由三个大件组成（见 `STream3R.__init__`）：

```startLine:25:34:stream3r/models/stream3r.py

self.camera_head = CameraHead(dim_in=2 * embed_dim)

self.depth_head  = DPTHead(dim_in=2 * embed_dim, output_dim=2, activation="exp",     conf_activation="expp1")
```

## 二、阶段 1：图像编码（Shared-weight ViT Patch Embed）

`STreamAggregator` 用 **DINOv2 ViT-L/14 (with registers)** 作为 patch embedder（也可换 ViT-S / ViT-B / ViT-g）：

- 输入 `[B, S, 3, H, W]` → 用 ImageNet 均值方差做归一化 → reshape 成 `[B*S, 3, H, W]`；
- 每张图独立 patch embed，得到 `[B*S, P, C]`（C=1024）；
- 拼接两类**特殊 token**到每一帧前面：
  - `camera_token`：1 个，承担"该帧相机位姿"信息；
  - `register_token`：4 个（DINOv2 风格的寄存器 token，吸收 outlier 激活）。
- `patch_start_idx = 1 + 4 = 5`，方便后续 head 区分特殊 token 与图像 patch；
- 位置编码用 **2D RoPE**（`RotaryPositionEmbedding2D`），特殊 token 的位置坐标设成 0，patch 的位置 +1 偏移以错开。

> 关键设计：**双套 special token** —— "锚帧 vs 非锚帧"

```startLine:96:99:stream3r/models/components/aggregator/streamaggregator.py
# Note: We have two camera tokens, one for the first frame and one for the rest
# The same applies for register tokens
self.camera_token   = nn.Parameter(torch.randn(1, 2, 1, embed_dim))
self.register_token = nn.Parameter(torch.randn(1, 2, num_register_tokens, embed_dim))
```

第 0 套 token 给序列的**首帧（锚帧）**用，第 1 套 token 给**其它帧**用。这与 DUSt3R 把第一帧作为世界坐标系原点的设定一致——首帧扮演"参考帧 / anchor"，后续帧都向它做对齐。
流式推理时（`StreamSession`），如果 KV cache 已经有锚帧了，新来的帧就一律用第 1 套 token（见 `slice_expand_and_flatten` 中的 `is_anchor_exist`）。

## 三、阶段 2：因果解码器（STreamAggregator 的总体结构）

解码器一共有 **24 层（depth=24）**，但每一层不是单一注意力，而是按 `aa_order = ["frame", "global"]` 交替执行：

- `frame_blocks`：24 个**帧内自注意力**块
- `global_blocks`：24 个**跨帧（可因果）注意力**块

每次循环里先 frame 后 global（`aa_block_size=1`），然后把两者输出**沿通道拼接**作为该层中间表示：

```startLine:217:222:stream3r/models/components/aggregator/streamaggregator.py
for i in range(len(frame_intermediates)):
    # concat frame and global intermediates, [B x S x P x 2C]
    concat_inter = torch.cat([frame_intermediates[i], global_intermediates[i]], dim=-1)
    output_list.append(concat_inter)
```

这就是为什么三个 head 的 `dim_in = 2 * embed_dim`——它们消费的是 **frame ⊕ global** 的拼接表示。

- token 形状变成 `(B*S, P, C)`，**每一帧自己内部做 self-attention**，帧与帧之间互相**看不到对方**；

- 这一阶段不需要 mask，也不用 KV cache。

## 五、阶段 4：跨帧因果注意力（Global Causal Attention）

```startLine:264:287:stream3r/models/components/aggregator/streamaggregator.py
def _process_global_attention(self, tokens, B, S, P, C, global_idx, pos=None, attn_mask=None, kv_cache=None):
    if tokens.shape != (B, S * P, C):
        tokens = tokens.view(B, S, P, C).view(B, S * P, C)
```

- token 形状变成 `(B, S*P, C)`，**把所有帧的所有 token 拉成一条长序列**；
- 在这条长序列上做 self-attention，但加 mask 控制时间方向：

```startLine:148:170:stream3r/models/components/aggregator/streamaggregator.py
if mode == "causal":
    for i in range(S):
        curr_view_start = i * P
        curr_view_end   = (i + 1) * P
        mask[curr_view_start:curr_view_end, curr_view_end:] = float('-inf') 
elif mode == "window":
    window_size = 5
    for i in range(S):
        curr_view_start = i * P
        curr_view_end   = (i + 1) * P
        mask[curr_view_start:curr_view_end, P:] = float('-inf')
        start_view = max(1, i - window_size + 1)
        mask[curr_view_start:curr_view_end, start_view*P:(i+1)*P] = 0
elif mode == "full":
    mask = None
```

这一段是整篇方法的"灵魂"，体现了三种推理模式：

| 模式 | mask 规则 | 含义 | 用途 |
|---|---|---|---|
| `causal` | 第 i 帧的所有 patch 只能 attend 第 0..i 帧 | 严格 GPT 式因果 | 默认流式模式，可 KV-cache |
| `window` | 第 i 帧只能看 **首帧（锚帧）+ 最近 5 帧** | 因果 + 滑动窗口 | 显存恒定，超长序列首选 |
| `full` | 不加 mask | 退化为双向，全图对齐 | 离线模式，类似 VGG-T |

注意 window 模式还**永远保留首帧（锚帧）的可见性**（`P:` 截断时 `start_view = max(1, ...)`），因为锚帧定义了整段重建的世界坐标系。

> KV cache 的关键：因为 causal，新来一帧 i 的 Q 只需和**历史所有帧的 K/V**做 attention。`StreamSession` 在每次 `forward_stream` 里把每层 `global_block` 的 K/V append 到 `aggregator_kv_cache_list`，下一帧来时直接读，**省掉对历史帧的重复计算**。所以 README 才能给出 `causal/window` 模式下的运行时和显存表。

## 六、输出头：双坐标系点图 + 置信度 + 位姿

`aggregator` 输出 `aggregated_tokens_list`（每层一个 `[B, S, P, 2C]` 中间表示），三个 head 各取所需：

### 1. CameraHead — 输出 9 维相机位姿

只取每帧的 `camera_token`（`tokens[:, :, 0]`），然后送入一个 **4 层小 trunk**：

```startLine:113:127:stream3r/models/components/heads/camera_head.py
# Use tokens from the last block for camera prediction.
tokens = aggregated_tokens_list[-1]
# Extract the camera tokens
pose_tokens = tokens[:, :, 0]
pose_tokens = self.token_norm(pose_tokens)

B, S, C = pose_tokens.shape
attn_mask = None
if kv_cache_list is None:
    attn_mask = self._create_attn_mask(S, mode, ...)
```

- trunk 内同样支持 `causal/window/full` 三种 mask（保持流式一致性）；
- **迭代 4 次** refine，每次把上一次预测的 9 维 pose 通过 `embed_pose` 转回 token，做 AdaLN 调制（DiT 风格的 `shift / scale / gate`），再过 trunk，预测 Δpose 累加；
- 输出格式 `absT_quaR_FoV` = **3 维平移 + 4 维四元数旋转 + 2 维 FoV**，共 9 维。

### 2. point_head (DPTHead) — 世界坐标系点图

```startLine:32:32:stream3r/models/stream3r.py
self.point_head = DPTHead(dim_in=2 * embed_dim, output_dim=4, activation="inv_log", conf_activation="expp1")
```

- `output_dim=4`：3 维 XYZ + 1 维 confidence；
- 输出 `world_points: [B, S, H, W, 3]`、`world_points_conf: [B, S, H, W]`；
- 用的是 DUSt3R/VGG-T 同款的 **DPT 解码器**，把多层 token concat 后上采样回原图分辨率；
- "世界坐标系"在 STream3R 里就是**首帧（锚帧）相机的坐标系**——所有非锚帧的点图都被映射到这个统一坐标系。

### 3. depth_head (DPTHead) — 相机坐标系深度

```startLine:33:33:stream3r/models/stream3r.py
self.depth_head = DPTHead(dim_in=2 * embed_dim, output_dim=2, activation="exp", conf_activation="expp1")
```

- `output_dim=2`：1 维 depth + 1 维 confidence；
- 输出 `depth: [B, S, H, W, 1]`、`depth_conf: [B, S, H, W]`；
- 这就是你说的"**相机坐标系下的点图**"——给定 depth 和 CameraHead 预测的 FoV（即内参），任意像素都能反投影出当前相机系下的 3D 点 \(P_{cam} = \pi^{-1}(u, v, d; K)\)。

### 三个输出之间的几何一致性

`world_points`、`depth + pose` 在理想情况下应该满足：

\[
P_{world}^{(i)} = R_i^{\top} \big(\pi^{-1}(u, v, d_i; K_i) - t_i\big)
\]

所以训练时这三者会被多个损失同时约束（pointmap loss + depth loss + pose loss），互为正则，迫使模型学到几何一致的 3D 表征。

## 七、把整个 forward 串起来看

一次 `model(images, mode="causal")` 的完整数据流：

```
images [B, S, 3, H, W]
   │
   ▼  ① 图像编码
DINOv2 ViT Patch Embed  →  patch tokens [B*S, P, C]
   +  camera_token (anchor / non-anchor)  +  register_tokens
   +  2D RoPE
   │
   ▼  ② 因果解码（24 × {frame_block, global_block}）
for layer in 0..23:
     frame_block:  reshape (B*S, P, C),  ③ 帧内 self-attention
     global_block: reshape (B, S*P, C),  ④ 跨帧 causal/window/full attention
     concat → [B, S, P, 2C] 存入 aggregated_tokens_list
   │
   ├──► CameraHead   :  4 层 trunk × 4 次迭代 → pose_enc [B, S, 9]
   ├──► point_head   :  DPT 解码 → world_points [B, S, H, W, 3] + conf
   └──► depth_head   :  DPT 解码 → depth [B, S, H, W, 1] + conf
```

## 八、和其它方法的对比直觉

- **DUSt3R / MASt3R**：成对图像 → pointmap，然后**全局 BA 优化**拼接，离线、慢；
- **VGG-T**：一次性吃全部图像，**双向 full attention**，离线、显存随 S² 涨；
- **Spann3R / CUT3R**：流式但用简单的"记忆 token"，长序列退化；
- **STream3R**：把 VGG-T 的 full attention 改成 **causal**，并继承 VGG-T 预训练权重，本质是"**VGG-T 的 GPT 化**"——既保留了大规模 3D 先验（精度），又获得了流式能力（实时 / 长序列），训练侧也直接复用 LLM 的基础设施。

这也是它在 NRGBD 上能同时**击败 Stream 类方法**（Spann3R / CUT3R / StreamVGGT）和**离线 SOTA**（VGG-T、DUSt3R）的原因。

## 1. causal / window / full 三种模式的区别，以及与"参考帧（锚帧）"的关系

这三种模式都是**作用在跨帧（global） attention 的 mask**上的，**帧内自注意力（frame attention）从来都是双向的**，不受 mode 影响。

`STreamAggregator._create_attn_mask` 的逻辑：

```startLine:148:170:stream3r/models/components/aggregator/streamaggregator.py
if mode == "causal":
    for i in range(S):
        curr_view_start = i * P
        curr_view_end   = (i + 1) * P
        mask[curr_view_start:curr_view_end, curr_view_end:] = float('-inf') 
elif mode == "window":
    window_size = 5
    for i in range(S):
        curr_view_start = i * P
        curr_view_end   = (i + 1) * P
        mask[curr_view_start:curr_view_end, P:] = float('-inf')
        start_view = max(1, i - window_size + 1)
        mask[curr_view_start:curr_view_end, start_view*P:(i+1)*P] = 0
elif mode == "full":
    mask = None
```

把可见性画出来（"X" 表示能看到，"." 表示被 mask 掉），假设 S=6，window_size=5：

```
帧 0(anchor) 1 2 3 4 5
causal:
 帧0 →  X . . . . .
 帧1 →  X X . . . .
 帧2 →  X X X . . .
 帧3 →  X X X X . .
 帧4 →  X X X X X .
 帧5 →  X X X X X X

window (W=5):
 帧0 →  X . . . . .
 帧1 →  X X . . . .
 帧2 →  X X X . . .
 帧3 →  X X X X . .
 帧4 →  X X X X X .
 帧5 →  X X X X X X     ← 注意此时 W=5，覆盖帧 1..5，恰好也能看到帧 0
 帧6 →  X . X X X X X   ← 滑窗扔掉帧 1，但锚帧 0 始终保留！
 帧7 →  X . . X X X X X

full: 全是 X（双向，no mask）
```

### 和"参考帧 / anchor frame"的关系

**是的，三种模式都建立在"第一帧是世界坐标系锚帧"的前提上**，体现在两个地方：

1. **window 模式特意保留锚帧的可见性**：注意 `start_view = max(1, i - window_size + 1)`——下界**永远从 1 开始**，再加上前面 `mask[:, P:] = -inf` 先把所有非锚帧屏蔽（即"先把锚帧 0 列单独保留"），所以**锚帧的 token 任何后续帧都看得到**。这样滑窗到第 100 帧时，新帧仍然能"参考"第 0 帧定义的世界坐标系，不会漂移。

2. **special token 有"锚帧版 / 非锚帧版"两套**：

```startLine:96:99:stream3r/models/components/aggregator/streamaggregator.py
# Note: We have two camera tokens, one for the first frame and one for the rest
self.camera_token   = nn.Parameter(torch.randn(1, 2, 1, embed_dim))
self.register_token = nn.Parameter(torch.randn(1, 2, num_register_tokens, embed_dim))
```

`slice_expand_and_flatten` 给第一帧用 index=0 的 token，其它帧用 index=1 的。这样模型从最开始就"知道"哪一帧是锚帧、要把它当成世界坐标系原点。
流式推理中（`StreamSession`），当 KV cache 已经存在时（`is_anchor_exist=False`），新来的帧一律用 "非锚帧" token——因为锚帧已经在缓存里固定下来了。

总结：

| 模式 | mask | 显存 | 锚帧可见性 | 使用场景 |
|---|---|---|---|---|
| `causal` | 严格因果 | O(S²) | 总可见（i≥0） | 默认流式，支持 KV cache |
| `window` | 因果 + 滑窗(5) + 强制保留锚帧 | O(1) 恒定 | 永远可见 | 超长序列、实时 |
| `full` | 无 mask（双向） | O(S²) | 锚帧 token 仍特殊 | 离线模式，类似 VGG-T |

## 2. 能否换成 DINOv3？token 数量怎么算？位置编码细节

### token 数量：你算对了大部分

token 数计算：**每帧 token 数 = patch 数 + 5 (special)**，其中 5 = 1 (camera) + 4 (register)。

```startLine:91:94:stream3r/models/components/aggregator/streamaggregator.py
# The patch tokens start after the camera and register tokens
self.patch_start_idx = 1 + num_register_tokens   # = 5
```

不过 24×24 = 576 这个数对应的是 **336×336** 的输入（336/14 = 24）；STream3R 仓库**默认的 `img_size=518`**：

- 518/14 = 37 → 37×37 = **1369 patch tokens/帧**
- 加上 special token 后 = **1374 tokens/帧**
- 跨帧 attention 上看到的总长度 = S × 1374

如果你按 H=W=336 跑（或者像 README 评测用的 518×384 → 37×27 = 999），都是符合 `H/patch_size × W/patch_size + 5` 这条公式。**你说的 576 + 5 = 581 在 336×336 的设定下是对的**。

### 换 DINOv3：技术上可行，但有 4 个适配点

```startLine:112:135:stream3r/models/components/aggregator/streamaggregator.py
vit_models = {
    "dinov2_vitl14_reg": vit_large,
    "dinov2_vitb14_reg": vit_base,
    "dinov2_vits14_reg": vit_small,
    "dinov2_vitg2_reg": vit_giant2,
}
self.patch_embed = vit_models[patch_embed](
    img_size=img_size, patch_size=patch_size,
    num_register_tokens=num_register_tokens, ...
)
```

要换 DINOv3 需要注意：

1. **接口兼容**：当前从 patch_embed 输出取 `x_norm_patchtokens`（dict），DINOv3 的官方实现接口要保持一致（或写一层 wrapper）。
2. **维度对齐**：当前 `embed_dim=1024` 是 ViT-L 的；DINOv3 ViT-L 也是 1024 可以直接用；但 ViT-7B 的 hidden dim 不同，要改 `embed_dim`，下游 head 的 `dim_in = 2 * embed_dim` 跟着变。
3. **patch_size**：当前 14；DINOv3 公开版本主推 16，意味着同样输入分辨率下 token 数会变（518/16 ≈ 32，token 数变成 1024），RoPE 的 frequency 也建议重新搜。
4. **register tokens**：DINOv3 默认带 4–8 个 register（和 DINOv2-reg 一致），可以保留 `num_register_tokens=4`。
5. **DPT 取层**：`intermediate_layer_idx=[4, 11, 17, 23]` 是按"24 层 transformer 在 1/4、1/2、3/4、最后"取的，DINOv3 不同规格层数变了要同步调整。
6. **预训练权重失配**：最致命的一点——STream3R 是从 **VGG-T checkpoint**初始化的（VGG-T 用 DINOv2 ViT-L/14），换 DINOv3 等于换 backbone，**必须重新做大规模 3D 预训练**，否则下游头会和新 backbone 对不上特征空间。

所以"能换"，但工程上不是改个名字这么简单；如果只是想刷点性能，建议先在 DPT 上做 LoRA / adapter 验证，再考虑换 backbone。

### 位置编码：2D RoPE（沿 y 和 x 各做 1D RoPE）

源码核心：

```startLine:175:194:stream3r/models/components/layers/rope.py

horizontal_features = self._apply_1d_rope(horizontal_features, positions[..., 1], cos_comp, sin_comp)

```

具体规则：

- **每个 patch token 带一个 (y, x) 整数坐标**（通过 `PositionGetter` 生成 `torch.cartesian_prod(y, x)`）；
- 把 token 的 head_dim 一分为二：**前半通道用 y 做 1D RoPE，后半通道用 x 做 1D RoPE**；
- 1D RoPE 公式跟 LLaMA / GPT 一样：`q ⊙ cos + rotate(q) ⊙ sin`，base frequency = 100；
- RoPE **每一层 attention 都加**（不是只加一次），施加在 q/k 上；
- **特殊 token 的位置全部设为 0**，patch 坐标整体 +1 避免与之撞值：

```startLine:198:206:stream3r/models/components/aggregator/streamaggregator.py

    # do not use position embedding for special tokens (camera and register tokens)
    # so set pos to 0 for the special tokens

    pos_special = torch.zeros(B * S, self.patch_start_idx, 2).to(...)
    pos = torch.cat([pos_special, pos], dim=1)
```

**关键观察**：跨帧 global attention 把所有帧拼成长序列 `(B, S*P, C)` 时，**沿用的还是同一套 2D RoPE 坐标**——也就是说**没有任何"时间维度"的 position embedding！时间顺序信息完全由 causal mask 编码**。这一点和 GPT 一样（GPT 用 RoPE 表达 token 内部相对位置，用 causal mask 暗示先后），但 STream3R 是把这套思想搬到了"帧"的粒度。

## 3. "图像编码之后经过了因果解码"是什么意思？

这里的"**因果解码**"是论文里 decoder-only Transformer 的说法，含义是：

**整个 24 层堆叠的 STreamAggregator 是一个 decoder（解码器），而不是 encoder + decoder 的双塔结构**。"解码"在这里**不是生成像素**，而是从图像 token 中"解码"出几何信息（pointmap、depth、pose）。

| 概念 | 在 STream3R 中的含义 |
|---|---|
| Encoder | 仅指 ViT patch embed（每帧独立编码成 tokens） |
| Decoder | 后续 24 层 frame+global block 堆叠 |
| Causal | 仅作用在**帧维度**：第 i 帧的 token 看不到第 j>i 帧的 token |
| 不是 | "逐 token 自回归生成下一帧"——它不预测下一帧图像 |

更具体一点：

```
图像 [S 帧]
   │
   ▼  ① 图像编码 (Encoder)
   ViT patch embed (24 层 DINOv2)：每帧独立 → tokens [S, P, C]
   │
   ▼  ② 因果解码 (Decoder, 24 层)
   for layer in 0..23:
      frame_block(每帧内 full self-attn)
      global_block(跨帧 attn, 第 i 帧只看 0..i 帧)   ← "因果"在这里
   │
   ▼  ③ Head
   pointmap / depth / pose
```

为什么叫"因果"？参照 GPT：

- GPT 里 token t 只能 attend t' ≤ t，所以叫 causal LM；
- STream3R 里**帧 i 只能 attend 帧 j ≤ i**，把"因果性"从 token 维度搬到了帧维度。

这样做的实际意义有 3 个：

1. **流式可用**：第 i+1 帧来了，0..i 帧的 K/V 全部可以从 cache 复用，只算新 Q；
2. **训练并行**：跟 GPT 一样，一次 forward 就能算出所有帧的预测（teacher forcing 风格），不需要逐帧 rollout；
3. **天然向"下一帧预测"对齐**：未来想做 4D / 视频生成扩展时（仓库提到的 4RC），保持因果方向就能直接接 next-frame 预测目标。

## 4. trunk 是什么？2D 怎么过渡到 3D？

### "trunk" 一词

"trunk" 在深度学习里通用意思就是"主干网络"。在 STream3R 里它出现在 `CameraHead`，指代**位姿预测头里那个 4 层 Block 组成的主干 Transformer 序列**：

```startLine:55:64:stream3r/models/components/heads/camera_head.py
self.trunk = nn.Sequential(
    *[
        Block(
            dim=dim_in,
            num_heads=num_heads,
            mlp_ratio=mlp_ratio,
            init_values=init_values,
        )
        for _ in range(trunk_depth)   # trunk_depth=4
    ]
)
```

CameraHead 的工作流：

1. 从 `aggregated_tokens_list[-1]` 取每帧第 0 个 token（即 `camera_token`），shape `[B, S, 2C]`；
2. 把它送入 trunk（4 层 Transformer Block，同样支持 causal/window/full mask）；
3. **迭代 4 次（refinement）**：每次用上一轮的 9 维 pose，通过 `embed_pose` 嵌回 token 维度，做 DiT 风格的 **AdaLN-zero 调制**（shift/scale/gate），再过 trunk，预测 Δpose 累加；
4. 最后输出 `pose_enc_list`，取最后一次作为最终预测；
5. 输出 9 维 = **3 维平移 + 4 维四元数 + 2 维 FoV**（`absT_quaR_FoV`）。

> 类比："trunk" 之于 head 就像 "backbone" 之于 model——是 head 内部用于反复 refine 的小型主干。

### 2D 到 3D 的过渡：DPTHead 是关键桥梁

`point_head` 和 `depth_head` 都用同一个 `DPTHead`（Dense Prediction Transformer，源自 Depth-Anything 系列），它把**序列形式的 token "重塑成 2D 特征图"，再多尺度融合上采样到原图大小，最后每个像素输出 3D 量**。

完整流程：

```startLine:215:255:stream3r/models/components/heads/dpt_head.py
for layer_idx in self.intermediate_layer_idx:   # [4, 11, 17, 23]
    x = aggregated_tokens_list[layer_idx][:, :, patch_start_idx:]   # 去掉 special token

    x = x.view(B * S, -1, x.shape[-1])
    x = self.norm(x)
    x = x.permute(0, 2, 1).reshape((x.shape[0], x.shape[-1], patch_h, patch_w))   # ← 关键：token → 2D feature map

    x = self.projects[dpt_idx](x)
    if self.pos_embed:
        x = self._apply_pos_embed(x, W, H)
    x = self.resize_layers[dpt_idx](x)

    out.append(x)
    dpt_idx += 1

out = self.scratch_forward(out)
out = custom_interpolate(out, (H, W), mode="bilinear", align_corners=True)

if self.pos_embed:
    out = self._apply_pos_embed(out, W, H)

out = self.scratch.output_conv2(out)
preds, conf = activate_head(out, activation=self.activation, conf_activation=self.conf_activation)
```

分步看：

**Step 1: 取多尺度中间层 token**

从 24 层 aggregator 中按 `[4, 11, 17, 23]` 取 4 个中间层（相当于浅/中/深/最深 4 个层次），每层去掉 5 个 special token，只留 patch tokens。

**Step 2: token → 2D feature map（这是 2D 到 3D 的真正"形状转换"起点）**

```python
x = x.permute(0, 2, 1).reshape((x.shape[0], x.shape[-1], patch_h, patch_w))
# (B*S, P, C) → (B*S, C, patch_h, patch_w)
```

把"P 个 patch token 的 1D 序列"重新摆成 patch_h × patch_w 的 2D 网格，因为 ViT 的 patch 本来就是按 (i,j) 网格切出来的，这一步只是逆操作。**到这一步 feature map 还是 patch 分辨率（H/14 × W/14）**。

**Step 3: 多尺度对齐**（仿 FPN）

不同层用不同上下采样比例搭出特征金字塔：

```startLine:73:87:stream3r/models/components/heads/dpt_head.py
self.resize_layers = nn.ModuleList(
    [
        nn.ConvTranspose2d(out_channels[0], out_channels[0], kernel_size=4, stride=4),  # 浅层 ×4 上采
        nn.ConvTranspose2d(out_channels[1], out_channels[1], kernel_size=2, stride=2),  # 中层 ×2 上采
        nn.Identity(),                                                                   # 维持
        nn.Conv2d(out_channels[3], out_channels[3], kernel_size=3, stride=2, padding=1), # 最深层 ÷2 下采
    ]
)
```

**Step 4: RefineNet 自顶向下融合**

`refinenet4 → refinenet3 → refinenet2 → refinenet1`，每次把当前融合结果上采样、加上相应尺度的 skip，是经典 DPT 的 FPN 解码塔。

**Step 5: 上采到原图分辨率**

`custom_interpolate(out, (H, W))` → 双线性插值回到 H×W。

**Step 6: 像素级激活，输出 3D 量**

```python
out = self.scratch.output_conv2(out)   # 3x3 conv + ReLU + 1x1 conv → output_dim 通道
preds, conf = activate_head(out, activation=self.activation, conf_activation=self.conf_activation)
```

对两个 head 而言：

| Head | `output_dim` | `activation` | 输出含义 | 最终 shape |
|---|---|---|---|---|
| `point_head` | 4 | `inv_log` (无界 XYZ) | 3 维世界系 XYZ + 1 维 conf | `world_points [B,S,H,W,3]`, `world_points_conf [B,S,H,W]` |
| `depth_head` | 2 | `exp` (保证 >0) | 1 维相机系深度 + 1 维 conf | `depth [B,S,H,W,1]`, `depth_conf [B,S,H,W]` |

`conf_activation = "expp1"` 即 `exp(c)+1`，保证置信度 ≥ 1（DUSt3R 同款写法）。

### 2D 到 3D 的"本质过渡"在哪里？

它不在某一行代码，而是分散在三层：

1. **隐式 3D 表征的学习**：跨帧 causal attention 让每个 patch token 不仅含本帧像素特征，还含**与其它帧的对应关系**——这是经典 multi-view stereo 思想"对应即深度"的 Transformer 化。在大规模 3D 数据上训练后，token 实质上编码了"这个像素在 3D 空间中的位置"。
2. **形状还原 + 多尺度融合**：DPT 把 1D token 序列 reshape 回 2D 网格 + FPN 上采，使得每个像素都能拿到几何特征。
3. **激活函数选择决定输出语义**：`inv_log` 给无界 XYZ 用，`exp` 给必须为正的 depth 用，最后一卷积层把 C 维特征映成 3 个数（XYZ）或 1 个数（depth）+ 1 个 conf——这就完成了 **2D image → per-pixel 3D quantity** 的最后一公里。

并且 `point_head` / `depth_head` / `camera_head` 三者在训练时同时被监督，**几何一致性损失**会迫使三者满足
\[
\text{world\_points}(u,v) \;\approx\; R^{\top}\bigl(K^{-1}[u,v,1]\cdot d(u,v) - t\bigr)
\]
这样 2D → 3D 的映射在训练时不仅"学得出"，还"几何上自洽"。
