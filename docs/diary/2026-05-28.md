# 关于图像、视频搜索：

## 数据挖掘：

### 对于autonomous driving的刚需：

自动驾驶模型的能力上限由它见过的数据分布决定，而真实驾驶数据是极度长尾的，99% 是平淡场景，决定模型成败的是不到 1% 的长尾数据，在这种分布下随机采样几乎一定低效，百万级标注预算大部分会浪费在无增益的重复样本上；同时，量产/路测的 disengagement 修复有"7 天内闭环"的硬约束，没有系统化挖掘，靠肉眼翻日志或关键词过滤要么慢要么漏，而挖掘把"一个 case → 一类 case"的时间从周级压到小时级，直接成为团队迭代速度的乘数；再加上生成式时代世界模型、视频生成、仿真都需要被 condition，seed 必须从真实数据中检索而来，挖掘已经从单纯服务训练数据建设，演变为同时支撑训练、验证、生成三条主线的共用地基；而其投入产出比同样不对称——系统本身是几人月一次性投入加持续算力开销，优化的却是后端动辄千万级的标注和训练支出，扎实的 data mining 通常能把"训出同精度所需样本数"降到 1/3 到 1/5，这个 ROI 在 AD 这种数据驱动的领域几乎没有替代品。

## AD数据挖掘架构演进

### 架构设计原则：基于模态的分层建设

Module 1(文本->图像、视频)：基础且成熟的模块，当前业务线的基石工作；

Module 2(图像->图像、视频)：本次报告中的核心，当前阶段的攻坚方向；

Module 3(视频->图像、视频)：远期规划，面向未来的探索性方向。

### Module 1: 文本 -> 图像、视频（已实现）

Q? 能不能看看已有的效果

已经有完善的产线，文本侧和视觉侧共享空间，然后进入Filter进行筛选比对。

文本搜索的天花板由文字本身的描述粒度决定，有四个结构性的限制：1. 无法很好的描述长尾场景；2. 依赖image-text pair训练分布；3. 视觉细节信息丢失严重，纹理、几何关系、布局、运动模式等被特征被压缩；4. 冷启动门槛，不同的描述差异性极大，结果不稳定。

*文本检索不下线，不投入大改造，继续作为粗筛和冷启动入口存在*

### Module 2: 图像 -> 图像、视频（研究核心）

1. 重要性、必要性：Module 1的瓶颈卡住了数据闭环效率。

（1）工程师的事迹工作流是"贴图找类似"，不是"写描述找类似"。当一个 disengagement 或 bad case 出现，工程师手里第一时间拥有的是那一帧图像或那段视频本身——这是天然的 query。中间强行插入一步"先把这个场景翻译成文字"既不准确，又拖慢闭环。系统应该顺着用户的真实工作流走，而不是反过来。

（2）长尾和 corner case 本质上"看得见但说不出来"。这正是 AD 数据挖掘最有价值的部分——能用文字描述清楚的场景，通常已经不长尾了。文本检索的能力曲线在长尾区域显著衰减，而长尾恰恰是模型迭代收益最高的区域，这是一个错配。

（3）图搜图天然对齐模型 failure 的形态。模型输出错的那一帧 / 那一段，本身就是 image / video tensor。把它直接当 query，零信息损失。文本路径需要先把它 caption 化，再用 caption 检索——多了一层信息瓶颈，而且 caption 生成本身就可能是错的。

（4）它是后续多模态复合 query 的地基。"用这张图 + 这段轨迹形状 + 这条线路 ID，找类似场景"这种复合 query 是数据挖掘的终态，而它的前提是图、轨迹、元数据各自都能独立成为 query。图搜图是其中算法链路最长、风险最高的一环，不先把它跑通，后面所有复合 query 都是空中楼阁。

2. 优势：

（1）召回粒度细: 视觉相似度直接捕获纹理、几何、布局、光照——这些是文本编码不出来的。

（2）零冷启动: 任何工程师都会贴图，不需要培训"怎么写好 query"。

（3）天然覆盖长尾: 不依赖文本词表，任何能被相机看到的场景都能成为 query 和被召回对象。

（4）失败模式高对齐: bad case → query 是直接的 tensor 操作，无需中间翻译。

（5）训练免图文标注: SSL backbone (DINOv2/v3、V-JEPA-2) 不需要 image-text pair，可以直接在自家车队数据上做 continual pretrain，域适配成本低。

3. 风险点：

（1）挖掘粒度选型：

T1 环境主导：给定一个视觉环境，让DINO去找到类似的视觉环境；

T2 行为主导：找前车cut-in后自车急刹的clip，依赖时序运动的pattern，纯靠DINO基本不可行；

T3 混合行为：依赖环境+行为，DINO有较大影响。

（2）评测集选择：

评测集是后续所有模型选型与版本迭代的客观尺，必须先于模型选型完成；它本质上是项目级别的 loss function，设计错了，后面所有数字都不可信。

核心原则：评测集必须匹配系统当下能做的事，不要用 v3 的能力清单评 v1 的系统。在初期 DINO + FAISS baseline 阶段，纯视觉模型不具备 tag 挖掘能力，评测集就不该包含行为 / tag / 复合 query，否则会把"评测集设计错"误判成"模型不行"。

评测集与系统能力对齐演进：

| 阶段 | 系统能力 | 评测集应包含 | 不该包含 |
|---|---|---|---|
| S0 DINO + FAISS baseline | 纯视觉相似检索 | 视觉相似性、近重复、place recognition | tag query、行为 query、复合 query |
| S1 + ROI / 多向量 | + 物体级检索 (Mode B) | + 物体相似性 | 同上不变 |
| S2 + 时序头 | + 静态主导视频检索 (T1) | + 视频环境相似 | 行为 query 仍不该评 |
| S3 + 轨迹塔 / 分类器 | + 行为 / tag mining (T2/T3) | 才开始加行为评测集 | — |

S0 阶段评测集 v0.1 设计 (200 query × 4 layer，1 周可建完，不依赖 tags100)：

L1 近重复 / 变换鲁棒性 (~50 query)：同一 clip 不同时刻、不同光照下的两帧自动配对，augmentation 生成 positive。Ground truth 几乎全自动，测 DINO 下限。

L2 同地点 / Place Recognition (~50 query)：用 GPS 自动配对"100 米半径内、同方向、不同 trip"的 clip，纯几何标签零标注成本，测 DINO 对环境主导 query (T1) 的核心能力，也测 NeoLix 路线重复度高这个不对称优势能否被利用。

L3 纯视觉相似性 (~50 query)：VLM 跑 prompt 提议 top-30 候选 → 标注员只做 verify (✓/✗)，每条 query 5-10 分钟，200 条约 30 标注员·小时。测 DINO 在没有几何 / 标签先验下的 perceptual quality。

L4 物体级检索 (~50 query，Mode B 准备用)：用现有检测器在候选库跑出所有物体作为粗 ground truth，人工补 hard cases。测 DINO patch token 的细粒度能力，提前给 Mode B 留评测位置。

S1+ 阶段评测集独立维护：tag 分类器评测 (每个 tag 一份独立 binary classification testset，200-500 正 + 500-1000 负含 hard neg) 与 retrieval 评测集完全独立，分别迭代。复合行为 query 评测最贵，最后才建。

关键认知：

- 不要把所有评测合到一份；不同能力分开评测，各自迭代。
- 不要用 tags100 标签当 DINO retrieval 的 ground truth，那是把别人的不确定性引入自己的评测体系。
- GPS、几何、VLM 都是免费的 ground truth 信号，能让 v0.1 评测集 1 周建完而不是数月。
- 物体级 (L4) 提前埋种子，避免"先有系统再补评测"的反复返工。

（3）模型选型：

模型选型必须建立在 (2) 评测集已就绪的前提下，没有客观尺的选型只是声音大的人主导的口水战。这条依赖链不能逆转。

把"模型选型"拆成 3 个具体决策，每个决策给"主选 + 备选 + 排除选项"，避免开放式比较：

决策 a · 视觉 backbone：

| 候选 | 推荐度 | 理由 |
|---|---|---|
| DINOv2 / DINOv3 | 主选 | retrieval benchmark SOTA，可 continual SSL，无需图文对，工程成熟 |
| SigLIP-2 | 备选 | 跨模态联检索强，但纯视觉 fidelity 略弱于 DINO；保留作粗筛 / 文字入口 |
| EVA-CLIP | 备选 | OK 但活跃度不如 SigLIP |
| Qwen3-VL / InternVL 当 encoder | 排除 | 训练目标是生成不是度量，pool 损失大、推理几秒不可承受 |

决策 b · 视频 backbone：

| 候选 | 推荐度 | 理由 |
|---|---|---|
| DINOv2 + 轻量 temporal head (8-15M 参) | 主选 v1 | 工程友好，3-4 周可上，效果是上限版 70-80% |
| V-JEPA-2 | 升级 v2 | 效果上限高，但 checkpoint / finetune 工具链不成熟，作为 Q3-Q4 升级 |
| VideoMAE V2 | 备选 | 经典稳定，已被 V-JEPA-2 超越 |
| InternVideo2 | 排除 | 大、部署成本高 |

决策 c · VLM 在挖掘链路里的角色：

| 角色 | 是否上车 | 备注 |
|---|---|---|
| 在线 query encoder | 排除 | Qwen3-VL-235B 也做不到 retrieval-grade emb，且推理几秒不可承受 |
| 在线检索主力 | 排除 | 同上，延迟与成本均不可承受 |
| 离线 tagger / captioner | 上车 | 给数据库样本批量打 tag/caption，落 metadata 供在线 filter |
| 离线 top-K judge / reranker | 上车 | 高价值 bad case 精筛、复合 query "类似但是 X" 的语义校验 |
| 新 tag 冷启动 / bootstrap | 上车 | 没有训练数据时 zero-shot 挖出 seed，用作分类器的训练集起点 |
| 长尾 / rare tag 兜底 | 上车 | 触发频次极低、训不出分类器的 tag 持续由 VLM 服务 |

VLM 选型上，离线角色用 Qwen2.5-VL-7B 级别即可，不需要 235B；judge / 分类这种二值判断任务，规模上去后边际收益小但成本线性甚至超线性增长，235B 是浪费。

VLM 与分类器的关系是协作而非对立，长期演进路径分四阶段：阶段 0 VLM 主力挖出第一批 seed → 阶段 1 DINO + temporal head 上线，VLM 退到 top-K 精排 → 阶段 2 DINO + 轨迹塔融合精度反超 VLM，VLM 退到长尾兜底 → 阶段 3 DINO 主力承担 99% 流量，VLM 仅服务 1% 长尾 + 新 tag bootstrap。这条演进路径必须从立项第一天规划好，避免长期停留在"VLM 跑全库"这种短期可行但成本不可持续的状态。

（4）图像patchtoken应用到视频之后：

DINO 是单帧空间表征，对视频检索来说是"基础底座"不是"主角"。video query 的处理方案按工程量从轻到重分四档，实际落地按 a → c → d 演进：

档 a · Frame-level retrieval + 时间窗聚合 (1 周可上，MVP)：每帧独立 DINO 出 emb，检索后按 video_id 聚合邻近帧命中合并成 segment。不训新模型，跑通"图搜 clip"全链路。

档 b · DINO + temporal pooling (mean / GeM / attention pool)：冻结 DINO，跨 8 帧 pool 出单 clip emb。零或极少参数，但抹平时序顺序，T1 静态主导够用，T2 行为主导失效。

档 c · DINO + 轻量 temporal transformer head (~12-15M 参，推荐主力)：DINO 冻结，4 层 transformer 做时序聚合，8 帧 + CLS pool。单卡 1-2 天训完，T1 + 弱 T2 都能 cover。这是图搜视频第一版主力方案。

档 d · 原生视频 SSL backbone (Q3-Q4 升级)：不再用 DINO 做视频侧，直接换原生视频 SSL，运动 pattern 表征显著优于 c。可选 backbone：

| 模型 | 推荐度 | 备注 |
|---|---|---|
| V-JEPA-2 (Meta, 2024-2025) | 主选 | latent space masked prediction，motion-heavy 场景显著优于 DINO；多基于 DINO 权重初始化，前期 SSL 投资可复用 |
| VideoMAE V2 | 备选 | 经典 masked video modeling，稳定但已被 V-JEPA-2 超越 |
| InternVideo2 | 备选 | 多模态多 stage 训练，中文 / 驾驶场景表现好，但模型大、部署成本高 |
| VideoPrism (Google, 2024) | 观望 | 通用 video encoder，闭源，工程落地难 |
| ViCLIP / LanguageBind | 跨模态 | text-video 联检索，作为文搜视频专用通道，不替代图搜视频 |

补充方案 · 显式注入运动信号 (motion-aware)：DINO 看不到运动，可以通过外接 optical flow (RAFT / SEA-RAFT) 把"光流场"作为第二通道，与 DINO 空间特征 concat 或 cross-attn 融合。RAFT 仅 7M 参数，跨域几乎不掉点，是介于档 c 和档 d 之间的轻量补充，对运动信号敏感的 query 显著提升。

并行多塔 · 视频 + 轨迹联合表征：动态场景检索的最优架构是 DINO (空间) + V-JEPA-2 (时空) + 轨迹 Transformer (运动学) 三塔分工，各塔独立 SSL 后做晚期融合。低速无人物流车场景下，轨迹塔的性价比反而比视频塔高 (输入 KB 级、训练便宜、对 cut-in / 博弈类 query 判别力极强)，值得作为后续表征学习章节的重点投入。

DINO 在动态场景的角色边界：

能做：per-frame backbone；anchor-frame 代理 clip (T1 够用)；视频 SSL 模型的空间初始化 (V-JEPA-2 多基于 DINO 起点，SSL 投资可复用)；配合 temporal head 做轻量聚合；跨帧 appearance descriptor (供 SAM2 / tracker 用)；T3 复合 query 里的环境上下文快通道 (先用 DINO 砍候选 → 视频塔 / 轨迹塔精排)。

不能做：运动 pattern 编码 (cut-in / 急刹 / lane change 是时间一阶 / 二阶导)；长程时序依赖；跨帧对应；速度 / 加速度；temporal grounding (事件发生在第几秒)。

结论：行为级 query 不指望视觉塔单独解决。T2 行为主导场景，DINO 必须配合 V-JEPA-2 (视觉运动塔) 或更优的轨迹塔 (SceneTransformer / Wayformer 风格，吃 ego + agent 历史轨迹) 来共担。

### Module 3：视频 -> 图像、视频（未来展望）

视频作为 query 比图作为 query 多两个维度的难度: 时长不对齐和时序对齐。学术界 V-JEPA-2、VideoPrism、InternVideo2 路线都有进展，但工程成熟度和评测体系都明显落后于图搜图，且对算力和评测建设的投入比 Module 2 高一档。

## VLM和传统图文模型的分析

### 三种范式的本质差异

业内口语"VLM vs 传统图文模型"把两种很不同的非 VLM 模型混在了一起，准确说应分三种根本不同的范式：

A. 生成式 VLM（Qwen3-VL, InternVL, GPT-4V）: vision encoder + LLM decoder，next-token prediction 训练，输出文字。

B. 对比式跨模态（CLIP, SigLIP-2, EVA-CLIP）: dual encoder，图文 contrastive 训练，输出跨模态共享 embedding。

C. 自监督纯视觉（DINOv2/v3, V-JEPA-2, VideoMAE）: single encoder，self-distillation / masked prediction 训练，输出纯视觉 embedding，无文字通道。

关键差异：A 输出"文字"，本质做"理解 + 生成"；B / C 输出"向量"，本质做"度量空间"。B 是图文对齐，有文字通道；C 没有文字通道但视觉 fidelity 更高。"图文模型"严格说指 B，C 是纯视觉模型，本节用三分法精确区分。

### 能力对比矩阵（图搜 / 视频搜 × 三范式）

| 场景 | A 生成式 VLM | B 跨模态 (CLIP/SigLIP) | C 纯视觉 SSL (DINO/V-JEPA) |
|---|---|---|---|
| 图搜图 | ✗ encoder / △ tagger | △ | √ 主力 |
| 文搜图 | △ 离线 caption | √ 主力 | ✗ |
| 图搜视频 | ✗ / △ judge | △ frame-level | √ DINO+temporal / V-JEPA-2 |
| 文搜视频 | △ caption | △ frame-level + 聚合 | ✗ 需 ViCLIP / LanguageBind |
| 视频搜视频 | ✗ | ✗ | √ V-JEPA-2 / VideoMAE |

三种范式没有"通用最强"，每种场景都有它的主力。强行用一种范式覆盖所有场景，就是"用 VLM 做所有事"或"用 DINO 做所有事"两类典型项目走偏。

### 三种范式的能 / 不能

**A 生成式 VLM**

能做：离线 tagger（给数据库样本打 tag / caption）；top-K 精排 / pairwise judge；复合 query 的意图理解和 query rewriting；强 zero-shot；解释性输出。

不能做：高效产出 retrieval-grade embedding（hidden state pool 损失大且不为度量空间优化）；亿级在线检索（推理几秒到几分钟）；细粒度 perceptual 判别；输出非确定性。

定位：**离线工具，不进在线主链路**。

**B 对比式跨模态 (CLIP/SigLIP)**

能做：文搜图 / 文搜帧（设计目标）；跨模态联合 query；粗筛入口与冷启动；CIR 基座。

不能做：纯视觉 fidelity 弱于 C；AD 域漂移大；clip-level 视频检索无原生支持；长尾视觉特征捕捉差。

定位：**粗筛 + 文字入口 + 跨模态桥梁**。第一阶段直接用 SigLIP-2 即可，不是图搜主力。

**C 纯视觉 SSL (DINO/V-JEPA)**

能做：图搜图主力（retrieval benchmark SOTA）；物体 / 区域级检索（patch token 天然支持 ROI pool / 多向量 MaxSim）；图搜视频静态主导场景；视频搜视频（V-JEPA / VideoMAE）；continual SSL 域适配；作为 video SSL 的空间初始化；作为 tracker 的 appearance descriptor。

不能做：无文字通道；单帧 DINO 不编码运动；无自然语义解释；属性 decomposition 弱（全局 pool 把多属性混合编码）；跨域需 continual SSL。

定位：**图搜与视频搜的算法主干**，所有需要 perceptual fidelity 的场景由 C 担任。

### 工程参数对比

| 维度 | A VLM (Qwen3-VL-7B) | B SigLIP-L | C DINOv2-L |
|---|---|---|---|
| 单图编码耗时 (A100) | ~500-1000 ms | ~5 ms | ~5 ms |
| 235B 模型耗时 | ~3-10 s | — | — |
| 推理显存 | 16-200 GB+ | 4-8 GB | 4-8 GB |
| 自训 / continual 难度 | 极高 | 中 | 低（无标签） |
| 在线延迟可用性 | ✗ | √ | √ |

A 与 B / C 工程上不是一个量级。亿级候选库的在线检索 A 几乎不可能用，B / C 才是合理选项。VLM 的位置只能是离线 batch。

### NeoLix 数据挖掘三范式分工

在线主力（亿级、毫秒级）：

- 图搜图 / 物体搜 → C 纯视觉 SSL (DINOv2/v3)
- 视频搜视频 → C 视频 SSL (V-JEPA-2)
- 文搜图（粗筛入口） → B 对比式跨模态 (SigLIP-2)

离线工具（batch、分钟 - 小时级）：

- 给数据库打 tag → A VLM-as-tagger (Qwen2.5-VL-7B)
- 给数据库写 caption → A VLM-as-captioner
- top-K 精排 / 解释 → A VLM-as-judge

明确排除：

- A 当 retrieval encoder（Qwen3-VL-235B 也不行）
- A 当在线检索主力（延迟与成本均不可承受）

### 小结

三种范式没有"通用最强"——VLM 是离线工具，B / C 是在线主力，各自有不可替代的位置。DINO / V-JEPA 是 NeoLix 数据挖掘的算法主干（尤其图搜图、物体搜、视频搜视频），这条路线锁定后，后面所有架构都围绕这三个 backbone 展开。VLM 的核心价值不是"做检索"，而是"给检索的数据库打结构化 tag"和"给 top-K 做精排和解释"——这两个角色能为下游标注 / 挖掘节省巨额人工成本，但绝不能进在线主链路。

## 整体思路

时间轴 →

阶段 0 (week 1-4):
    VLM 主力,挖出第一批 5000 正样本作为 seed
    └─ 此时 VLM 既是"挖掘工具"也是"老师"

    DINO 路线持续 maintenance (continual SSL, 数据增量)
    VLM 仅在新 tag 立项时重新启用
